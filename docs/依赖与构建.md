# 依赖与构建方案

核实日期：2026-10-30，Asia/Shanghai。用户要求依赖使用最新版；本设计以**官方源的最新稳定版本**作为基线，不主动采用 RC、Preview 或 Experimental。

## 1. 版本政策

“用最新版”与“可重复构建”同时满足：开始实施 / 升级时查询最新稳定版，提交确切版本与完整传递依赖锁文件；普通构建使用锁定恢复，不在每次启动或构建时漂移到新版本。

此文档中的版本已直接查询 NuGet V3 flat-container、.NET 官方发布元数据、原生库官方 GitHub Release 与 Visual Studio 官方发行说明。检索摘要可能落后或互相矛盾，版本号以这些源为准。完整结果保存在 [dependency-baseline.json](dependency-baseline.json)。

**该 JSON 是调研基线，不是 NuGet 实际恢复得到的 `packages.lock.json`，也不代表整组依赖已经通过集成验证。**

## 3. C# 直接依赖

| NuGet 包 | 最新稳定版本 | 引用工程 | 作用 |
|---|---|---|---|
| `Microsoft.WindowsAppSDK` | **2.6.4** | UI | WinUI 3、窗口、系统背景；不在 Host / Explorer 引用 |
| `CommunityToolkit.Mvvm` | **8.4.2** | UI | ObservableObject、命令和源生成，减少 UI 样板代码 |
| `Jint` | **4.17.0** | ScriptHost | 纯 .NET JavaScript 解释器；脚本执行限额与模块 |
| `Microsoft.Extensions.Hosting` | **10.0.14** | Host | DI、生命周期、后台任务、日志抽象；不重复引入整套自建生命周期框架 |
| `Microsoft.Windows.CsWin32` | **0.3.367** | Host / UI 的 interop 工程 | 生成所需 Win32 绑定，`PrivateAssets=all` |
| `JsonSchema.Net` | **9.5.0** | ScriptHost 的候选验证模式 | 清单与自定义参数 JSON Schema 校验；网络引用禁用；Host 对结果执行固定的有界结构验证 |

JSON 序列化、命名管道、`TimeProvider`、`PeriodicTimer`、`BigInteger`、SHA-256、基础日志接口均优先使用 .NET 自带能力。不额外引入 Newtonsoft.Json、消息总线、SQLite、Node.js、Electron、Tauri 或 WebView2。

`Microsoft.Extensions.Hosting` 自带传递依赖所需的日志 / 配置模块。若代码因打包边界需直接引用 `Microsoft.Extensions.Logging` 等包，应使用同一稳定补丁版本并重新核实依赖图，不为了“统一表格”无用途地增加直接引用。

NuGet 版本来源为各包官方 flat-container `index.json`，具体 URL 见机器可读基线；例如 [Windows App SDK](https://api.nuget.org/v3-flatcontainer/microsoft.windowsappsdk/index.json)、[Jint](https://api.nuget.org/v3-flatcontainer/jint/index.json)、[MVVM Toolkit](https://api.nuget.org/v3-flatcontainer/communitytoolkit.mvvm/index.json)。

## 4. C++ 原生模块依赖

| 库 | 最新稳定版本 | 使用方式 |
|---|---|---|
| 自有 NativeBridge / DLL 控制接口 | 原生 ABI **v1** | 加载、握手、状态、租约与逻辑分离；随本项目版本发布 |
| MinHook | **1.3.4** | 确有必要时用于内部布局函数钩子，静态链接；不负责注入；x86/x64 库，不据此声称 ARM64 支持 |
| C++/WinRT 生成器 / 头文件包 | **3.0.260818.1** | 从最新稳定包生成 / 引用自有工程投影，统一头文件来源；Explorer 内使用系统 XAML 类型 |
| Windows Implementation Library | **1.0.260126.7** | header-only RAII、句柄与错误辅助；仅引入实际使用的头文件 |
| nlohmann/json | **3.12.0** | header-only，解析有界显示快照；不要把全量工资 / 脚本传给原生模块 |

原生库在开发机 / CI 恢复并编入自身二进制，不在最终用户机器编译。WIL、nlohmann/json 与 C++/WinRT 从表中固定 NuGet 包恢复到构建依赖目录，由 `restore-native-deps.ps1` 提供 CMake 的明确 include / 工具路径；不假设 C++ 工程可以无配置地使用托管 PackageReference。

MinHook 从官方固定 release 源码恢复，校验源码归档哈希并静态构建；实际工程恢复时生成原生依赖锁与 `native-assets.json`，记录版本、来源、哈希和许可证。不要在 Explorer 运行时联网拉取库或符号，也不把随意检出的主分支作为发布依赖。

原生 CMake 工程使用稳定 MSVC 支持的 C++23 特性，先不开启 C++ modules。若最新稳定库或编译器与任务栏适配冲突，应记录并适配代码 / 重新选型，不能悄悄降级后仍声称使用最新版。MinHook 与 CFG、优化、并发回调的组合也进入 P0 门禁。

资料：[WIL](https://github.com/microsoft/wil)、[C++/WinRT](https://github.com/microsoft/cppwinrt)、[nlohmann/json](https://github.com/nlohmann/json)、[MinHook 1.3.4](https://github.com/TsudaKageyu/minhook/releases/tag/v1.3.4)。

## 6. 版本锁定文件

实施时根目录添加：

```json
{
  "sdk": {
    "version": "10.0.403",
    "rollForward": "disable",
    "allowPrerelease": false
  }
}
```

仓库已写入 `global.json` 并通过项目本地 SDK 实际构建，同时为新测试工具链配置 `Microsoft.Testing.Platform` runner。使用 `scripts/bootstrap-dotnet.ps1` 可安装到忽略的 `.tools` 目录，不修改系统 SDK。

`Directory.Packages.props` 示例：

```xml
<Project>
  <PropertyGroup>
    <ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>
  </PropertyGroup>
  <ItemGroup>
    <PackageVersion Include="Microsoft.WindowsAppSDK" Version="2.6.4" />
    <PackageVersion Include="CommunityToolkit.Mvvm" Version="8.4.2" />
    <PackageVersion Include="Jint" Version="4.17.0" />
    <PackageVersion Include="Microsoft.Extensions.Hosting" Version="10.0.14" />
    <PackageVersion Include="Microsoft.Windows.CsWin32" Version="0.3.367" />
    <PackageVersion Include="JsonSchema.Net" Version="9.5.0" />
    <PackageVersion Include="Microsoft.NET.Test.Sdk" Version="18.11.0" />
    <PackageVersion Include="xunit.v3" Version="4.0.2" />
    <PackageVersion Include="xunit.runner.visualstudio" Version="4.0.1" />
    <PackageVersion Include="coverlet.collector" Version="10.1.0" />
  </ItemGroup>
</Project>
```

每个托管工程生成并提交 `packages.lock.json`；普通 CI 执行 `dotnet restore --locked-mode`。WiX 工程的 SDK 版本在 `.wixproj` 固定。NuGet lock 不负责 Windows SDK 安装包、原生源归档、MSVC 或 CMake / Ninja，另在工具链 manifest 与原生依赖锁中记录版本与 SHA-256 并校验下载内容。

不添加 `Version="*"`，不使用 floating `10.*`。所有传递依赖遵守官方兼容约束并锁定；不能强行把每个传递包升级到彼此不兼容的最高版本。

## 7. 工程属性与发布

目标系统首版为 Windows 11 24H2+ x64，实际支持的具体构建由任务栏适配验证决定。当前实际构建差异见[实现进展](实现进展.md)：稳定 SDK 不接受 28000 TFM，因此实现采用 26100 TFM + 最新 28000.87 引用包，不使用 Preview 开关。

- Core / ScriptHost 可用 `net10.0`；需要 Windows 互操作的 Host / UI 使用 `net10.0-windows10.0.28000.0`，编译引用最新 SDK，`SupportedOSPlatformVersion` 设为 `10.0.26100.0`。
- UI 设置 `UseWinUI=true`；普通 EXE 采用对应 Windows App SDK 版本的 unpackaged 部署属性。
- 发布使用 `RuntimeIdentifier=win-x64`、`SelfContained=true`、UI 的 `WindowsAppSDKSelfContained=true`，运行时补丁固定为 `10.0.14`。
- 首版 `PublishTrimmed=false`、`PublishSingleFile=false`、不启用 NativeAOT；WinUI 与 Jint 先按官方支持方式发布，优化另做实测。
- `WindowsSdkPackageVersion` 如需显式指定，使用核实的 SDK.NET.Ref 版本 `10.0.28000.87`；SDK 引用解析与 App SDK 2.6.4 的兼容性必须通过首次恢复 / 编译门禁。
- 开启 nullable、源分析器和确定性构建；`System.Text.Json` 为 IPC DTO 使用源生成元数据，限制最大深度。
- NativeBridge / Taskbar DLL 采用 CMake `Ninja` + MSVC x64，固定 Windows SDK；原生运行时使用静态 CRT（`/MT`），WIL / JSON 为头文件依赖，MinHook 静态链接。跨模块 C ABI 不传递 STL 或堆内存所有权。
- 交付标准 EXE / DLL 和兼容清单，不生成 `.wh.cpp` 模块，不要求目标机器安装原生框架。原生 DLL 分版本目录安装并保守驻留到 Explorer 退出，见[自带任务栏组件](自带任务栏组件.md)。

以上属性为目标配置，不能取代一次真实工程恢复和发布验证。发布包内所有依赖文件按 SDK 输出一起安装，不手工挑选几个 DLL。

## 8. 升级流程

1. 查询官方源，排除包含预发布后缀的版本；GitHub Release 同时要求非 prerelease / 非 draft。
2. 更新依赖基线，明确直接依赖、工具链和由系统提供的能力。
3. 执行 NuGet 重新恢复，检查传递依赖与目标框架变化，生成新的 lock。
4. 运行核心计算 / 脚本限制 / IPC 测试；WinUI 编译发布，并在干净 Windows 环境打开设置和详情。
5. 如涉及原生模块、编译器、MinHook 或 Windows 更新，复跑 P0 引导、布局、逻辑分离、休眠重连和驻留版本升级测试。
6. 更新版本和来源后合并。发布继续使用验证过的确切版本。

预览版只有用户明确要求采用时才进入主构建。新的稳定版与当前接口不兼容时，应升级代码适配并验证，不能以保留旧版本掩盖未完成升级。
