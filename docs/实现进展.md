## 已确认的工具链差异

- 本机原生实验用现有 MSVC 19.44 / VS 2022、Windows SDK 26100 和 CMake 4.2.0。
- 最新发布工具链基线是 VS 2026 18.11.2、Windows SDK 28000、CMake 4.4.5；当前机器尚未安装 / 验证完整基线，发布门禁保持未通过。
- 即使使用 .NET SDK 10.0.403，稳定 C# TFM 检查仍不接受 `windows10.0.28000.0`。UI 使用受支持的 `net10.0-windows10.0.26100.0`，同时显式引用最新 SDK.NET.Ref `10.0.28000.87`，未改用 Preview 开关。
- 原型不需要 MinHook，也未引入 WIL 或 MVVM Toolkit：实际实现可以直接解析已验证入口并使用系统控件；避免为满足依赖表而增加未使用库。它们属于设计时备选，不是已链接依赖。

## 复现入口

```powershell
./scripts/build.ps1 -PrototypeToolchain -Test
./scripts/run-dev.ps1 -Settings
./scripts/stop-dev.ps1
```

构建后的 `WorkFor.NativeBridge.exe --self-test` 仅操作自身测试进程。`--probe-explorer` 为严格门禁下的只读任务栏探测；`--attach-explorer --duration 10` 和 `--run-explorer` 会实际附着研究区域，仅对当前验证文件指纹开放。

持续原生会话使用 JSONL 状态输出，区别于 `--stdio` 的长度帧控制模式；Host 保持其 stdin 打开，关闭时先发送 EOF 请求逻辑分离。
